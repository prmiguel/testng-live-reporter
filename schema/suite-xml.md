# `testng.xml` suite file

ast-grep has **no XML language** (its built-in language table stops at Yaml/Json/Html), so the
suite file is read with `yq -p xml -o json`. `xmllint` can query XPath but cannot emit JSON.

## Elements and attributes captured

| Element | Attributes / children | Normalised field |
| --- | --- | --- |
| `suite` | `name`, `parallel`, `thread-count`, `configfailurepolicy`, `group-by-instances`, `preserve-order` | `suite.name/parallel/threadCount/configFailurePolicy/groupByInstances/preserveOrder` |
| `parameter` | `name`, `value` | `suite.parameters{}` or `suite.tests[].parameters{}` by level |
| `test` | `name`, `preserve-order`, `group-by-instances` | `suite.tests[].name/preserveOrder/groupByInstances` |
| `groups > run > include/exclude` | `name` | `suite.tests[].groups.include/exclude` |
| `packages > package` | `name` | `suite.tests[].packages` |
| `methods > include/exclude` | `name` | `suite.tests[].methods.include/exclude` |
| `classes > class` | `name` | `suite.tests[].classes` |
| `suite-files > suite-file` | `path` | `suite.suiteFiles` |
| `listeners > listener` | `class-name` | `suite.listeners` |

Not captured yet: `<method>` selectors inside `<class>`, `time-out`, `object-factory`,
`guice-stage`, `parent-module`, `verbose`, `data-provider-thread-count`, `skipfailedinvocationcounts`.

## yq behaviour

```bash
yq -p xml -o json poc/fixtures/testng.xml
```

yq writes XML attributes with a `+@` prefix and collapses a single child to an object while
repeating children become arrays. `poc/jq/suite.jq` normalises both shapes:

```json
{
  "file": "poc/fixtures/testng.xml",
  "name": "acme",
  "parallel": "methods",
  "threadCount": 4,
  "configFailurePolicy": "skip",
  "groupByInstances": "false",
  "preserveOrder": "true",
  "parameters": {"env": "ci", "browser": "chrome"},
  "tests": [
    {
      "name": "smoke",
      "preserveOrder": "true",
      "groupByInstances": null,
      "parameters": {},
      "groups": {"include": ["smoke"], "exclude": ["quarantine"]},
      "packages": [],
      "methods": {"include": [], "exclude": []},
      "classes": ["com.acme.tests.LoginTest", "com.acme.tests.api.ApiSmokeTest"]
    },
    {
      "name": "regression",
      "preserveOrder": null,
      "groupByInstances": "true",
      "parameters": {"tenant": "acme"},
      "groups": {"include": [], "exclude": []},
      "packages": ["com.acme.tests.*"],
      "methods": {"include": [".*"], "exclude": ["legacyFlow"]},
      "classes": ["com.acme.tests.PaymentDataProviderTest"]
    }
  ],
  "suiteFiles": ["ci/testng-ci.xml"],
  "listeners": ["com.acme.listeners.ReportListener"]
}
```

Parameters are scoped: suite-level ones go in `suite.parameters`, test-level ones in
`suite.tests[].parameters`. They are not merged, so an override is visible.

The DTD lives at <https://testng.org/testng-1.0.dtd>. Validate the file before scanning it if
the project may have drifted; yq will happily parse a structurally wrong suite.

## Why this is a separate pass

The suite is the **effective** run configuration: it can include/exclude groups, override
parameters and add listeners that no annotation shows. It is also often generated by CI, so a
committed file can be stale. Keep it in the catalog, but label it as declared configuration.
